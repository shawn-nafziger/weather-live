# weather-live: notes for Claude

Live data for Shawn Nafziger's Weather Intelligence project. Read `shawn-nafziger/weather-intelligence/CLAUDE.md` for who Shawn is and how we work (plain language first, PRs only, one step at a time on his PC, outcomes he can check). The product plan and design playbook are in the "Weather intelligence" Claude Project.

## Rules
- **SEO standards (Nov 10, 2026): read `tallorderdigital-site/docs/seo-standards.md` before changing the Almanac's templates, generator, addresses or publishing**, and follow its pre-publish checklist. The Almanac is the site's largest section, so its rules on readable-without-scripts text, plain links, structured data and never dropping a published page apply in full.
- **Code and config changes arrive as pull requests.** Only the two workflows commit straight to `main`: hourly touches `archive/` and `live/`; daily touches `history/`.
- **The daily workflow also publishes the Almanac** (`almanac/build.py --all` → the **`almanac-build` branch**, one commit replaced each run; then a `repository_dispatch` with the secret `SITE_DEPLOY_TOKEN` asks `tallorderdigital-site` to republish, and its workflow copies the branch into `weather/almanac/`. Readers see it at **`tallorderdigital.com/weather/almanac/`**, part of the main site; Nov 10, 2026. The old `weather.tallorderdigital.com` addresses 301 there through Cloudflare redirect rules; setup in the README). Never commit to `almanac-build` by hand. `almanac/carry_over.py` runs before each handoff: a place that fails today's checks keeps its last good page, and a run that builds under 90% of the last run's pages hands nothing over. Every city page links to its six nearest places and the front page lists every place as plain links (Nov 10, 2026), so all pages are reachable without JavaScript. Links inside the Almanac stay relative, and every absolute Almanac address comes from `ALMANAC` in `build.py`. Pages are built per run and never committed. Every sentence is chosen from the city's numbers and checked; a city whose check fails is skipped, not published. Wording rules and decisions: the "Weather intelligence" Project doc `almanac-dashboards-plan.md`.
- **Records pages (Nov 12, 2026):** each place also gets `weather/almanac/<place>/records/` (`almanac/records.py` + `almanac/records_template.html`): every date's record high and low with the years that set them, each month's records, the all-time extremes and a chart of the year. Built in the same run, right after the place's overview, from the same record; every sentence is checked and a failed check skips only that page (`carry_over.py` keeps its last good version, and its 90% guard counts records pages separately). Titles: the overview owns "[City] Weather History", the records page "[City] Record Low and High Temperatures" (shorter fallback for long names; ≤62 characters). Second stations in a city that has its official record (New York (JFK), New York (LaGuardia), Dallas (Love Field), Austin (Bergstrom), Washington (Dulles)) get no records page, so they don't compete with the city's own (`records.has_branch_pages`). Overview and records link to each other (tabs), records pages link the six nearest records pages, and both are in the Almanac sitemap. Record high is orange and record low blue in the records page's intro, strip and chart (Shawn's call, Nov 10, 2026). Plan: the "Weather intelligence" Project doc `almanac-branch-pages-proposal.md` (rain, frost dates, state pages and snowfall come next, each as its own PR).
- **The Almanac is open to search engines (Nov 9, 2026; was `noindex` as a preview).** `build.py` writes each page's canonical link, share tags and schema.org JSON-LD (city pages: WebPage, Dataset, Place, breadcrumbs; front page: CollectionPage), fills the section headings and sentences into the HTML as well as the page script (so crawlers that don't run JavaScript read them), and writes `almanac/sitemap.xml` (listed in the main site's `robots.txt`). The organization and website ids match the main site's (`tallorderdigital-site/tools/structured-data.js`). Don't add `noindex` back to the templates; plan and checklist: `tallorderdigital-site/docs/seo-plan.md`.
- **`history/` is the official record**, one folder per place split by decade (`history/<place>/<decade>.csv`, via `scripts/history_store.py`; never read or write the files directly), refreshed for the last 21 days each run; days are replaced, never dropped.
- **The archive is permanent:** never edit, rewrite or delete files under `archive/`. Forecasts are kept per issue time. Fixes go forward only, with a note in the README.
- **Store metric, keep what the source said:** forecasts keep the NWS °F value and a °C copy; observations are °C as received.
- **Label honestly:** "so far" values come from hourly readings and can differ from the official next-morning high/low by a degree or two. Forecast-based statements say "forecast", "on pace for" or "would rank".
- **Ranks** (`scripts/ranks.py`): one official station series only, whole °F, "years strictly warmer + 1", always with the count ("of 155 since 1872"). Today and forecasts are ranked only where `rank_today` is true. "Typical" cutoff (warmest/coolest fifth) is Shawn's editorial call.
- **GitHub's runner uses Python 3.12; Claude's workspace defaults to 3.13.** Don't use 3.13-only features (e.g. `Path.read_text(newline=...)` broke the Nov 3, 2026 records runs). `/usr/bin/python3.12` is available locally, and the Tests workflow runs every PR on 3.12.
- Claude's cloud workspace **can't reach api.weather.gov or ACIS**; test with the offline fixtures in `tests/` and say so. The real test is a manual **Run workflow** on GitHub.
- No personal email in the NWS User-Agent; it identifies the site and this repo.
- All paths and cities come from the top of `scripts/nws_pull.py`, `config/cities.json` (hourly + daily), `config/hourly_metros.json` (hourly forecast archive for 46 more metro areas; slug + station only, the rest from the Almanac list; readings not archived) and `config/almanac_cities.json` (daily and Almanac only). After a daily run, read `history/status.json` to see which places updated, failed or are waiting; Claude can read it from git even when the Actions log server is unreachable.

- **Site header (Nov 9, 2026):** the Almanac templates (`almanac/template.html`, `almanac/index_template.html`, `almanac/records_template.html`) carry the main site's menu (NBA, Weather, More stories | About, Subscribe, search, light/dark), pinned header and phone hide-on-scroll, between `site-header:start` / `site-header:end` markers. Don't edit those blocks or the `<nav class="site-nav">` by hand: they're written by `python3 <tallorderdigital-site>/tools/apply-header.py almanac/template.html almanac/index_template.html almanac/records_template.html`; re-run it whenever the site's header changes. The Almanac keeps its own light/dark script (it redraws the charts), which the tool leaves alone.

- **Runs are started by a Cloudflare Worker** (`cloudflare/worker.js`, crons `7 * * * *` and `37 11,15 * * *` UTC); GitHub's schedule is only a backup. The Worker's token expires Oct 29, 2027 (see README).
